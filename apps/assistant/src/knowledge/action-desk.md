# Action Desk

Tivmark Action Desk gives a business one front door for customer, public, and
employee requests. A person can explain what they need in ordinary language;
Mark helps match that need to the team's live service catalog, shows the exact
request for confirmation, and creates a durable record only after approval.

Every team starts with four adaptable services:

- Sales consultation for product questions, requirements, plans, and demos.
- Customer support for product, account, order, or troubleshooting help.
- Software access for employee applications, workspaces, and entitlements.
- General request for needs that do not yet fit a specialized service.

Owners and administrators can add business-specific services, pause services,
set the intended audience, and define a response target. This makes the same
interaction pattern useful for returns, appointments, citizen services,
facilities, vendor intake, onboarding, and other workflows.

Requests move through Open, In progress, Waiting on requester, Resolved, or
Canceled. Each transition creates an activity event, so both the Tivmark web
workspace and Mark present status from the same authoritative record. Members
see their own requests; owners and administrators can operate the team queue.

Mark does not guess a service or claim success from conversation alone. For a
signed-in user it reads the current team catalog, uses the returned service id,
and sends the confirmed write through Tivmark's delegated API. Tivmark remains
the identity, authorization, and system-of-record boundary.
